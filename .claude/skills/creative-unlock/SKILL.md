# Creative Unlock

## Why this exists

The default failure mode when animating a script is to treat the transcript as
a checklist: read a sentence, put that sentence on screen, add a fade, move to
the next sentence. The result is technically animated but not actually a
motion graphic — it's subtitles with a background. It plays safe because
"safe" is easy to justify (it's literally what the script says), but safe is
also boring, and the viewer feels that immediately even if they can't name why.

The fix isn't more animation on the same idea. It's a different idea. A script
is the *meaning* to be delivered, not a shot list to be rendered.

## Core rule

**Do not just follow the words. Find the deeper visual idea.**

The script is the starting point, not the ceiling. Interpret, simplify,
expand, dramatize, and improve the visual direction whenever that produces a
stronger result. A line of narration is a hint about what the viewer should
understand and feel — your job is to design the scene that delivers that,
even if the scene looks nothing like the sentence.

## What you have permission to do

- Think beyond the literal sentence — design for the *idea*, not the words.
- Invent visual metaphors when a metaphor explains the concept faster or more
  memorably than a literal depiction would.
- Add supporting motion, UI chrome, symbols, rhythm, and structure when it
  makes a scene easier to read or more satisfying to watch.
- Remove text entirely when the visual already carries the message — a
  caption that repeats what's on screen is dead weight, not reinforcement.
- Combine, split, reorder, or re-weight beats from the script. A script beat
  is not sacred; the viewer's understanding is. If three sentences are really
  one idea, give them one bigger scene instead of three small ones.
- Improve a weak scene idea instead of executing it faithfully. If the
  obvious visual for a line is dull, it's your job to find a better one, not
  to ship the dull one because it's "accurate."

## How to think about each beat

Before building a scene, sit with these questions:

1. **What is this line really saying** — underneath the specific words?
2. **What should the viewer feel here** — curious, relieved, alarmed, amused,
   convinced?
3. **What visual would make this easier to understand than the sentence
   does?**
4. **What motion would make this more satisfying to watch** — a snap, a
   reveal, a collision, a transformation?
5. **What can be removed** so the scene reads clean at a glance?
6. **What can be added** so the scene feels alive rather than static — depth,
   parallax, a background that breathes, an element that reacts?

Answer these before writing any component code. If the honest answer to "what
would make this easier to understand" is "the sentence, as text, on screen" —
that's the rare case where text-forward is actually correct. Most of the time
it isn't.

## What to avoid

- Don't recreate the script word-for-word on screen.
- Don't caption every sentence as its own beat by default — that's the
  animated-subtitles trap this skill exists to prevent.
- Don't stay safe when the concept clearly needs a stronger visual idea. A
  correct-but-boring scene is a failure, not a safe fallback.
- Don't over-explain with clutter — multiple captions, labels, and diagrams
  competing for attention in one frame is worse than one clear idea.
- Don't treat this as permission to be inaccurate. The visual can be a
  metaphor; the underlying concept it teaches still has to be true. Protect
  the meaning, invent the execution.

## How this pairs with scene-composition

This skill is the mindset — it tells you to look past the literal sentence.
The `scene-composition` skill is the toolkit — it tells you *what kinds of
visuals* to reach for (UI panels, icons, metaphors, timelines) and how little
text to use once you've found the real idea. Use this skill to find the idea,
then use scene-composition to build it.
