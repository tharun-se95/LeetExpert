## Caption

Jump Game looks like a search over every sequence of jumps. On one array of 22 numbers that search makes 1,048,576 lookups. Tracking a single number makes 21.

Each number is the maximum jump from that index. Can you reach the last index?

The literal reading is a search: from each index try every jump length and recurse. On [20, 19, ..., 1, 0, 0], an array built so that every path ends on the same 0, that is 1,048,576 array lookups before it answers false.

The reframe: you never have to decide which jump to take. Sweep left to right keeping one number, the farthest index reachable so far. If the index you're standing on is ever past it, you're stuck. 21 lookups, same answer.

It is safe because the reachable indices are always a solid prefix: reach index i and you can reach everything up to i + nums[i], with no index skipped. A prefix is fully described by its right end. The number records a capability, not a decision.

## Alt text (per slide)

**Slide 1.** Cover. Greedy. 1,048,576 lookups, or 21. Same 22 numbers. Jump Game: track the farthest reach, never the path.

**Slide 2.** The problem. Can you reach the last index? nums[i] is the *maximum* jump from index i. [2,3,1,1,4]: true. [3,2,1,0,4]: false: stuck at index 3.

**Slide 3.** The literal reading. Try every jump Python code: def can_jump_brute(nums, i=0): / if i >= len(nums) - 1: / return True / for step in range(1, nums[i] + 1): / if can_jump_brute(nums, i + step): / return True / return False. [20, 19, ..., 1, 0, 0]: 22 numbers: 1,048,576 lookups.

**Slide 4.** The reframe. You don't choose a jump Don't ask which sequence of jumps reaches the end. Ask: what is the *farthest index I can possibly reach* as I move left to right? If that ever falls behind the index you're standing on, you're stuck.

**Slide 5.** The code. One number, one sweep Python code: def can_jump(nums: list[int]) -> bool: / max_reach = 0 / last = len(nums) - 1 / for i in range(len(nums)): / if i > max_reach: / return False / max_reach = max(max_reach, i + nums[i]) / if max_reach >= last: / return True / return True.

**Slide 6.** Why it's safe. What you can reach is a solid prefix Reach index i and you can reach every index up to i + nums[i]. You are never forced to skip one. So the reachable indices are always [0, max_reach], and a prefix is fully described by its right end. The number records *a capability, not a decision*.

**Slide 7.** Count it. The same 22 numbers Try every jump: 1,048,576 lookups. Track the farthest reach: 21 lookups. Both answer: false.
