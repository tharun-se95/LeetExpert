## Caption

queue.pop(0) looks free. It moves every element left, every time.

A queue adds at the back and removes from the front. An array's end is cheap. Its front is its bad end: pop(0) in Python and shift() in JavaScript move every remaining element.

Dequeue once from A, B, C and 2 elements move. Drain a queue of 1,000 that way and it's 499,500 element moves.

The fix isn't faster shifting. It's not shifting: advance a head index and the array never moves, only the boundary that marks where the queue begins. 0 moves.

In Python that's collections.deque. JavaScript has no built-in deque, so know that you're paying O(n) when you call shift().

## Alt text (per slide)

**Slide 1.** Cover. Queues. `pop(0)` looks free. It moves every element left. A queue built on a list's front is quietly quadratic.

**Slide 2.** The problem. A queue needs both ends Add at the back, remove from the front. An array's end is cheap. Its front is its bad end. pop(0) in Python and shift() in JavaScript move every remaining element.

**Slide 3.** What it does. Removing the front, spelled out Python code: def dequeue_shift(items): / front = items[0] / for j in range(1, len(items)): / items[j - 1] = items[j] / items.pop() / return front. Dequeue once from A, B, C: 2 elements move.

**Slide 4.** Count it. Drain a queue of 1,000 Shift on every dequeue: 499,500 element moves. Move the front instead: 0 element moves.

**Slide 5.** The fix. Move the front, not the data Python code: def dequeue(self): / x = self.items[self.head] / self.head += 1 / return x. Advance a head index instead of shifting. The array never moves, only the boundary that marks where the queue begins.

**Slide 6.** In practice. Use the right tool Python: collections.deque, push and pop at either end in O(1). JavaScript has no built-in deque. For modest sizes shift() is often tolerated: know that you are paying O(n) when you do.
