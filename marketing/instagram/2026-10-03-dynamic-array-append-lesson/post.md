## Caption

Appending to an array isn't always O(1). Some appends copy everything.

A list sits on a fixed block of slots. When the block is full, the next append allocates a bigger one and copies every element over: that one append is O(n).

So why is append called O(1)? Because the block doubles. 1,000 appends trigger only 10 grows and 1,023 copies in total, about 1.02 per append.

Grow by 10 slots at a time instead and the same 1,000 appends cost 49,600 copies: 48 times more, and it gets worse as n grows.

That's what "O(1) amortized" means: averaged over the run, even though a single append can copy 512 elements.

Did you know which appends are the slow ones? 👇

## Alt text (per slide)

**Slide 1.** Cover. Arrays & Dynamic Arrays. Appending to an array isn't always O(1). Most appends are one write. A few copy the whole array first.

**Slide 2.** The setup. A list sits on a fixed block Underneath is a plain array, the backing store. Its capacity is how many slots it has. Its length is how many are used. The memory after it may belong to something else, so it cannot simply grow in place.

**Slide 3.** The slow append. Full? Copy everything. Python code: def append(self, value): / if self._length == self._capacity: / self._grow() / self._store[self._length] = value / self._length += 1 / def _grow(self): / self._capacity *= 2 / new_store = [None] * self._capacity / for j in range(self._length): / new_store[j] = self._store[j] / self._store = new_store. When length == capacity, append allocates a bigger block and copies every element over. That one append is O(n).

**Slide 4.** How much bigger?. 1,000 appends, two policies Double the capacity: 10 grows · 1,023 copies. Add 10 slots each time: 100 grows · 49,600 copies. Same appends, 48 times the copying.

**Slide 5.** Why doubling wins. Copies at 1, 2, 4, 8, … A geometric series: it sums to under 2n copies across n appends. Spread over n appends, that is O(1) each. A fixed increment copies again every c appends, re-moving the same early elements. It never escapes O(n) per append.

**Slide 6.** The name for it. O(1) amortized Average copies per append: 1.02. The costliest single append: 512 copies. Amortized means averaged over the whole run. One append can still be O(n).
