## Caption

Why += on a string inside a loop quietly goes quadratic.

Strings are immutable in Python and JavaScript. So result += w can't extend result: it allocates a new string and copies both halves in.

Join ["a", "b", "c", "d"] that way and you copy 1 + 2 + 3 + 4 = 10 characters. Collect the pieces in a list and join once: 4.

At 1,000 one-letter words it's 500,500 copies against 1,000. That's O(n² · L) against O(n · L).

Honesty note from the lesson: CPython and V8 often special-case += and hide this. The builder is the version whose cost you can prove.

## Alt text (per slide)

**Slide 1.** Cover. Strings. `+=` on a string in a loop re-copies what it already built. Strings are immutable. Every `+=` builds a brand-new one.

**Slide 2.** The trap. It looks like one step per word Python code: def join_bad(words): / result = "" / for w in words: / result += w / return result. Strings are immutable. result += w allocates a new string of len(result) + len(w) and copies both in.

**Slide 3.** Count the copies. Join a, b, c, d += each time: 1 + 2 + 3 + 4: 10 character copies. Collect, then join once: 4 character copies. Every step re-copies the whole prefix it already built.

**Slide 4.** The fix. Collect the pieces. Join once. Python code: def join_good(words): / parts = [] / for w in words: / parts.append(w) / return "".join(parts). parts.append(w) stores a reference, not characters. "".join(parts) allocates once and copies each word once.

**Slide 5.** At scale. 1,000 one-letter words += in the loop: 500,500 copies · O(n² · L). Collect, then join: 1,000 copies · O(n · L). The triangular sum again: L + 2L + … + nL. The gap only widens as n grows.

**Slide 6.** Honesty note. Your interpreter may hide it CPython and V8 both special-case += on strings when the reference is private, often making it linear in practice. Rely on that and your cost depends on interpreter internals. The builder is the version whose cost you can *prove*.
