## Caption

You can binary search a 2D matrix without ever flattening it.

Search a 2D Matrix makes two promises: each row is sorted, and each row starts above where the previous one ended. Chain them and the whole grid, read row by row, is one sorted sequence.

So binary search the index range 0 to rows × cols − 1 and turn each midpoint k back into a cell: row = k // cols, col = k % cols. The flattened array is never built.

On a 100 × 100 matrix that's at most 14 cell reads instead of 10,000.

When a problem hands you a stronger promise, use it.

What does k = 6 map to in a 3 × 4 grid? 👇

## Alt text (per slide)

**Slide 1.** Cover. Matrix / 2D Traversal. Binary search a 2D matrix. No flattening needed. It's a sorted array wearing a grid costume.

**Slide 2.** The setup. Two promises about the matrix Each row is sorted, left to right. The first value of each row is greater than the last value of the row before. Chain them: read row by row, the whole grid is *one sorted sequence*.

**Slide 3.** The trick. One index, two coordinates Which row: k // cols. Which column: k % cols. Binary search the virtual indices from 0 to rows × cols − 1 and translate each midpoint back into the grid. The flattened array is never built.

**Slide 4.** The code. Ordinary binary search, one new line Python code: def search_matrix(matrix, target): / rows, cols = len(matrix), len(matrix[0]) / lo, hi = 0, rows * cols - 1 / while lo <= hi: / mid = (lo + hi) // 2 / value = matrix[mid // cols][mid % cols] / if value == target: / return True / if value < target: / lo = mid + 1 / else: / hi = mid - 1 / return False.

**Slide 5.** One step. Find 3 in the 3 × 4 example First midpoint, k = 5: row 1, col 1 · value 11. Cells read to find it: 4. 11 is too big, so everything from k = 5 onward is discarded in one move.

**Slide 6.** At the limit. A 100 × 100 matrix Scan every cell: 10,000 reads · O(m·n). Binary search, worst case: 14 reads · O(log(m·n)). When a problem hands you a stronger promise, use it.
