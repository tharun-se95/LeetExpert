## Caption

Keep a stack's minimum in one variable. It works until you pop the minimum.

Design a stack with push, pop, top and getMin, all in O(1). The obvious version keeps a single min variable and updates it on every push.

Push -2, 0, -3 and getMin says -3. Pop, and the stack holds [-2, 0]. The variable still says -3, a value that is gone. The new minimum is whatever was minimal before it arrived, and one overwritten variable has destroyed that.

The patch is to rescan the stack on every getMin: 500,500 elements read to empty a stack of 1,000, asking for the minimum before each pop.

The fix: pops undo pushes in exact reverse order, so snapshot the minimum alongside each push, on a second stack. Pop discards exactly the snapshot that expires. Same 1,000 values: 1,000 reads.

State that unwinds with the stack lives on a stack. Where else have you seen that? 👇

## Alt text (per slide)

**Slide 1.** Cover. Stacks. One `min` variable works. Until you pop the minimum. A stack that answers getMin in O(1), and the version that almost does.

**Slide 2.** The problem. A stack that knows its minimum push, pop, top and getMin, all in O(1). The obvious version keeps one min variable. Python code: def push(self, val): / self.stack.append(val) / if self.min is None or val < self.min: / self.min = val / def pop(self): / self.stack.pop().

**Slide 3.** Where it breaks. Pop the minimum push(-2), push(0), push(-3): getMin() → -3. pop(), and the stack holds: [-2, 0]. getMin() still says: -3. The new minimum is whatever was minimal before -3 arrived. One overwritten variable has destroyed that.

**Slide 4.** The patch. Rescan on every getMin Python code: class ScanMin(OneMin): / def getMin(self): / return min(self.stack). Correct, and no longer O(1). Empty a stack of 1,000, getMin before each pop: 500,500 elements read.

**Slide 5.** The insight. Keep the answer at every depth Pops undo pushes in exact reverse order. So snapshot the minimum of everything at or below this depth alongside each push. Pop discards exactly the snapshot that expires. State that unwinds with the stack lives *on a stack*.

**Slide 6.** The code. A second stack of minimums Python code: def push(self, val: int) -> None: / self._stack.append(val) / current_min = min(val, self._mins[-1]) if self._mins else val / self._mins.append(current_min) / def pop(self) -> None: / self._stack.pop() / self._mins.pop() / def top(self) -> int: / return self._stack[-1] / def getMin(self) -> int: / return self._mins[-1].

**Slide 7.** Replay. Nothing was lost The snapshots after three pushes: [-2, -2, -3]. pop(), then getMin(): -2. Empty a stack of 1,000, getMin before each pop: 1,000 elements read. Popping -3 exposes -2. The recovery is just reading what was never lost.
