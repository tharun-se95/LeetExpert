## Alt text (per slide)

**Slide 1.** Spot the bug: Rotate Array. A 2-line Python function, rotate: def rotate(nums, k): / nums[:] = nums[-k:] + nums[:-k]. It passes the sample test: rotate([1, 2, 3, 4, 5, 6, 7], 3) gives [5, 6, 7, 1, 2, 3, 4]. Find the input that breaks it. Comment it, then swipe.

**Slide 2.** Hint. The same code, with line 2 highlighted. Python slices never raise. What is nums[-k:] when k is bigger than the list?

**Slide 3.** The input that breaks it: rotate([1, 2, 3], 4). Leaves nums as [1, 2, 3]. It should be [3, 1, 2].

**Slide 4.** The fix. One line added. Add k %= len(nums). JavaScript, same bug: add k %= nums.length;.

**Slide 5.** Why. Rotating by len(nums) changes nothing, so only k % len(nums) steps matter. Past the length, the slices stop meaning what they look like. From the course: Rotate Array, in Arrays & Dynamic Arrays.

**Slide 6.** Closing slide: Passing the sample is not proof. Every problem in leetExpert, the interactive DSA course, has a sandbox: write it in Python or JavaScript and run the lesson's tests. leetexpert.com, link in bio.
