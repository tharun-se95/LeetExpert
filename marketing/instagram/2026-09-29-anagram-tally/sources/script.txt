Stop sorting to check anagrams. Listen and silent: same letters? Most people sort both words and compare. It works, but sorting costs O of N log N. Think Scrabble instead. Two racks of tiles. You wouldn't alphabetize them. You'd grab a tally sheet. Listen: each tile adds one. Silent: each tile takes one away. Every row back to zero? Same tiles. Anagram. Here's that in code. First, if the lengths differ, return false: they can't match. Counts is the tally sheet, a hash map from each letter to a number. For every letter in s, add one. For every letter in t, take one away. At the end, every count must be zero. That's one pass, O of N time. On a million letters, in our test run, sorting took over two hundred milliseconds. Counting took about a quarter of that. Warehouses reconcile stock the same way: plus one for every box in, minus one for every box out. The catch? Lots of solutions swap the map for a twenty-six slot array. That only covers A to Z. Give it café, and Python crashes: list index out of range. JavaScript is worse: it quietly says false. A hash map takes any character. And never compare sets. A A C C and C C A C have the same set of letters, but they're not anagrams. Counts matter. Hear same letters, any order? Say count them, out loud. Your turn: A A B versus A B B. Which rows miss zero?
