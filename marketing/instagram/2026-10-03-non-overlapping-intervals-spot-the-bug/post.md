## Alt text (per slide)

**Slide 1.** Spot the bug: Non-overlapping Intervals. A 9-line Python function, erase_overlap_intervals: def erase_overlap_intervals(intervals): / intervals.sort(key=lambda iv: iv[0]) / removed, end = 0, float("-inf") / for start, finish in intervals: / if start >= end: / end = finish / else: / removed += 1 / return removed. It passes the sample test: erase_overlap_intervals([[1, 2], [2, 3], [3, 4], [1, 3]]) gives 1. Find the input that breaks it. Comment it, then swipe.

**Slide 2.** Hint. The same code, with line 2 highlighted. The greedy keeps the first interval it sees. Which one should it see first?

**Slide 3.** The input that breaks it: erase_overlap_intervals([[1, 10], [2, 3], [4, 5]]). Returns 2. It should be 1.

**Slide 4.** The fix. One line changes. intervals.sort(key=lambda iv: iv[0]) becomes intervals.sort(key=lambda iv: iv[1]). JavaScript, same bug: intervals.sort((a, b) =&gt; a[0] - b[0]); becomes intervals.sort((a, b) =&gt; a[1] - b[1]);.

**Slide 5.** Why. Keep the interval that ends first, and it leaves the most room for the rest. Sorted by start, one long early interval blocks every short one after it. From the course: Non-overlapping Intervals, in Intervals.
