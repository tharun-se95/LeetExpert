## Caption

This function counts subarrays that sum to k. Delete the {0: 1} it starts with and it still runs. It just counts wrong.

How many contiguous subarrays sum to exactly k? You don't know the endpoints in advance, so the obvious answer tries every start and every end: 500,500 additions for 1,000 numbers.

The turn: a subarray's sum is one running total minus an earlier one. So at each position, ask a hash map whether an earlier running total equaled running - k. One question per number: 1,000 steps, same answer.

The map starts with {0: 1}, the empty prefix before index 0. Without it, a subarray that starts at index 0 has no earlier total to match. On [1, 2, 3] with k = 3 the answer is 2. Without the seed you get 1. No error, just a wrong count.

And unlike a sliding window, it works with negative numbers: it never shrinks anything.

## Alt text (per slide)

**Slide 1.** Cover. Prefix Sum. Delete `{0: 1}` and it still runs. It just counts wrong. Counting the subarrays that sum to k, in one pass.

**Slide 2.** The question. How many subarrays sum to k? You don't know the range's endpoints in advance. You're searching for them. Python code: def brute_count(nums, k): / count = 0 / for l in range(len(nums)): / total = 0 / for r in range(l, len(nums)): / total += nums[r] / if total == k: / count += 1 / return count. Every start, every end, 1,000 numbers: 500,500 additions.

**Slide 3.** The turn. Ask about the past instead A subarray's sum is one running total minus an earlier one. So at each position: has an earlier running total equaled running - k? A hash map remembers every running total so far. Each position asks it a single O(1) question.

**Slide 4.** The code. One pass Python code: def subarray_count(nums: list[int], k: int) -> int: / seen: dict[int, int] = {0: 1} / running = 0 / count = 0 / for x in nums: / running += x / count += seen.get(running - k, 0) / seen[running] = seen.get(running, 0) + 1 / return count.

**Slide 5.** The seed. Why it starts with {0: 1} It is the empty prefix, before index 0. Without it, a subarray that starts at index 0 has no earlier total to match. [1, 2, 3], k = 3, with the seed: 2 subarrays. The same call without it: 1.

**Slide 6.** Count it. 1,000 numbers, negatives included Every start, every end: 500,500 additions. One pass with the map: 1,000 steps. Subarrays that sum to 7, both ways: 4,402.

**Slide 7.** When to use it. Not a sliding window A sliding window needs a guarantee, typically all non-negative values, for its shrink step to be right. This never shrinks anything. It asks a hash map a question at every position, so negative numbers are fine. The cost: O(n) space instead of O(1).
