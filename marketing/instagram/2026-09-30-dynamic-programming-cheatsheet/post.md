## Alt text (per slide)

**Slide 1.** Cover. A leetExpert cheatsheet titled "Dynamic Programming", with a "Save this" tag. Tagline: "Subproblems + order — define the state before you code the loop." Chips list what is inside: 5 smells to patterns, 4 patterns, 3 targets and 3 traps.

**Slide 2.** Smell to pattern. Optimal among overlapping subproblems → DP table / memo. Count ways under constraints → Transition sum. Knapsack / decide take or skip → 2D then compress. Longest increasing / common subsequence → Sequence DP. Grid paths with obstacles → 2D fill from corners.

**Slide 3.** Pattern 1 of 4: State then transition. When: You can name ‘best/ways ending at i’. Name dp[i] (or dp[i][j]) in words first. Write the recurrence and base cases. Only then pick loop order — code without a named state is guesswork.

**Slide 4.** Pattern 2 of 4: Memoised recursion. When: Sparse reachable states; natural recursive structure. Top-down: same recurrence, cache results. Great when bottom-up would fill a huge unused table. Still state the complexity of the cache size.

**Slide 5.** Pattern 3 of 4: Rolling space. When: dp[i] only needs dp[i−1] (or two rows). Keep one or two rolling rows after the recurrence is correct. Compressing first is how people invent off-by-one bugs.

**Slide 6.** Pattern 4 of 4: Decision at each step. When: Take / skip, or choose among prior endings. Write the choices explicitly (take item j, end a subsequence at i…). Transitions that ‘feel right’ without listing choices usually miss a case.

**Slide 7.** Targets, time and extra space. 1D sequence DP: O(n·T) time, O(n) space (T = work per state). Classic knapsack: O(n·W) time, O(W) space (After rolling). Grid path DP: O(m·n) time, O(n)* space (*rolling column/row). Traps. Wrong iteration order: Bottom-up must evaluate dependencies before dependents. Reverse a loop and you silently read stale zeroes — tests pass on tiny cases, fail on real ones. Off-by-one base cases: Empty prefix, zero capacity, and the first cell of a grid are where most DP bugs hide. Write them before the nested loops. State that is not a decision point: If dp[i] cannot decide between alternatives at i, you are missing a dimension. Adding the choice to the state is cheaper than a wrong recurrence.

**Slide 8.** Closing slide: "The real Dynamic Programming cheatsheet, from the course." One of 21 cheatsheets in leetExpert, the interactive DSA course, each under its module's practice problems. leetexpert.com, link in bio.
