## Caption

Time isn't the only cost. Memory has a Big-O too, and some of it you never typed.

Space complexity is the same O machinery, applied to memory. One distinction does most of the work: total space counts the input, auxiliary space is only the extra you allocate. Auxiliary is what people mean by default.

Finding a max keeps one variable: O(1). Returning a sorted copy of 500 numbers allocates 500 more slots: O(n).

Then the memory you don't see. Every active call holds a stack frame, so adding 1 to 500 recursively stacks 501 frames; the loop uses 1. Same time complexity, different space.

And at 100,000 the recursive version isn't slow. It's a stack overflow.

Do you state space when you state time? 👇

## Alt text (per slide)

**Slide 1.** Cover. Big O & Complexity Analysis. Time isn't the only cost. Memory has a Big-O too. And some of that memory you never typed.

**Slide 2.** Two kinds. Total vs auxiliary space Total space counts everything, including the input. *Auxiliary* space is only the extra you allocate. It is what people mean by default, since the input's size isn't something you chose.

**Slide 3.** Same input, different extra. One variable, or a full copy Python code: def max_of(nums: list[int]) -> int: / best = nums[0] / for x in nums: / if x > best: / best = x / return best / def sorted_copy(nums: list[int]) -> list[int]: / return sorted(nums). max_of is O(1) auxiliary. sorted_copy is O(n): on 500 numbers, 500 extra slots.

**Slide 4.** The memory you don't see. Every call holds a stack frame Python code: def sum_to(n: int) -> int: / if n == 0: / return 0 / return n + sum_to(n - 1) / def sum_iter(n: int) -> int: / total = 0 / for i in range(1, n + 1): / total += i / return total. Recursion costs memory proportional to its depth, even if no frame allocates anything.

**Slide 5.** Measure it. Adding 1 to 500 sum_to: frames on the stack: 501. sum_iter: frames on the stack: 1. Same time complexity, different space.

**Slide 6.** And it crashes. At 100,000 it is not slow. It is an error. Python's recursion limit and JavaScript engines' stack sizes both turn sum_to on 100,000 into a stack overflow. From here on, stack depth is always part of the space answer.
