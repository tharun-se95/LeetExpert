## Caption

arr[7] doesn't search for index 7. It computes where it is. That one fact explains what arrays are good and bad at.

An array is one contiguous block of memory holding equal-sized slots. So the address of slot i is pure arithmetic: base + i × slot size. Base 4,096, 8-byte slots: index 3 lives at 4,120. No searching, O(1).

The price of being packed: no gaps allowed. Insert at the front and everything shifts. 1,000 front inserts cost 500,500 writes; 1,000 appends cost 1,000.

The hidden bonus: CPUs fetch a 64-byte cache line at a time, which holds 16 four-byte integers. Read one and the next 15 are already in cache.

When two designs tie on paper, bet on the contiguous one.

## Alt text (per slide)

**Slide 1.** Cover. Arrays & Dynamic Arrays. `arr[7]` doesn't search for index 7. It computes where it is. Why arrays are faster than they look.

**Slide 2.** What an array is. One contiguous block, equal-sized slots Because the slots are equal-sized and packed, the address of slot i is pure arithmetic. address(i): base + i × slot_size.

**Slide 3.** Do the math. Base 4,096, 8-byte slots Python code: def address(base, slot_size, i): / return base + i * slot_size. address(3): 4,120. No other position is touched. That is why arr[i] is O(1).

**Slide 4.** The price. Contiguity forbids gaps Python code: def insert_front(store, length, value): / for j in range(length, 0, -1): / store[j] = store[j - 1] / store[0] = value. Insert at the front and every element shifts one slot. It reads as one line and moves the entire array.

**Slide 5.** Count it. 1,000 inserts At the front: 500,500 writes. At the end: 1,000 writes. The triangular sum, n(n+1)/2: one of the most common accidental quadratics in real code.

**Slide 6.** The hidden superpower. Cache locality CPUs pull a cache line at a time, typically 64 bytes: 16 four-byte integers. Read arr[0] and the next 15 reads hit cache for free, about 94%. When two designs tie on paper, bet on the contiguous one.
