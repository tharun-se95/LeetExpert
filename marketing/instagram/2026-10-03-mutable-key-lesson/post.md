## Caption

Why can't a list be a dictionary key? Because of what happens when it changes.

A hash table computes a key's slot once, when you insert it, from the key's contents. The promise isn't "correct once". It's correct for as long as the key sits in the table.

So file an entry under [1, 2], then append 5 to that list. In our eight-slot table it was filed in slot 3; the lookup now goes to slot 0 and finds nothing.

The entry is still there. Nobody will ever compute its address again.

Python stops this at the type level: TypeError: unhashable type. A tuple works, because it's frozen the moment it's built. JavaScript doesn't stop you, so treat every key as frozen the instant you insert it.

Ever lost an entry this way? 👇

## Alt text (per slide)

**Slide 1.** Cover. Hash Tables. A list can't be a dict key. Here's what it would break. Python refuses to let you. JavaScript hands you the footgun.

**Slide 2.** The rule. Same key, same slot. Forever. A hash table computes a key's slot once, at insert time, from the key's contents. The promise is not "correct once". It is correct for as long as the key sits in the table.

**Slide 3.** How filing works. The slot comes from the contents Python code: def slot(key): / return sum(key) % 8 / class Table: / def __init__(self): / self.buckets = [[] for _ in range(8)] / def put(self, key, value): / self.buckets[slot(key)].append((key, value)). put runs the hash once and files the entry there. Nothing re-files it later.

**Slide 4.** Break it. Change the key after filing it Python code: def demo(): / table = Table() / key = [1, 2] / table.put(key, "parcel") / key.append(5) / return table, key. Filed under [1, 2]: slot 3. Looked up as [1, 2, 5]: slot 0 · not found.

**Slide 5.** The damage. Still stored. Never found. The entry is still in its old slot. The address and the object simply drifted apart, silently. No error, no warning: the table just starts lying to you.

**Slide 6.** What the languages do. Python refuses. JavaScript doesn't. Python: a list can't key a dict (TypeError: unhashable type). A tuple can, because its contents are frozen the moment it's built. JavaScript: nothing stops you mutating an object that is a Map key. Treat every key as frozen the instant you insert it.
