## Caption

Two correct functions. One finishes in a blink, the other takes days. A faster computer won't save it.

Two functions that both decide whether any two numbers sum to a target. Both correct. On 1,000 numbers one makes 499,500 pair checks, the other 1,000 set lookups.

At about 10⁸ simple operations a second, 100,000 numbers cost about 50 seconds against 1 millisecond. At 10,000,000: about 5.8 days against 0.1 seconds.

So buy a machine 100× faster? A linear algorithm handles 100× more data. A quadratic one, 10×. An exponential one, about 7 more elements.

The shape of the growth curve is a property of your algorithm, and no amount of hardware budges it.

What's the worst accidental O(n²) you've shipped? 👇

## Alt text (per slide)

**Slide 1.** Cover. Big O & Complexity Analysis. Same answer. One takes a blink. The other takes days. And a faster computer won't save it.

**Slide 2.** Two correct versions. Does any pair sum to the target? Python code: def has_pair_a(nums: list[int], target: int) -> bool: / n = len(nums) / for i in range(n): / for j in range(i + 1, n): / if nums[i] + nums[j] == target: / return True / return False / def has_pair_b(nums: list[int], target: int) -> bool: / seen = set() / for x in nums: / if target - x in seen: / return True / seen.add(x) / return False.

**Slide 3.** Count the work. 1,000 numbers, no matching pair Version A: check every pair: 499,500 pair checks. Version B: remember what you saw: 1,000 set lookups. Nothing about correctness distinguishes them. Only their growth does.

**Slide 4.** Scale it. At about 10⁸ operations a second 100,000 numbers: A: ~50 s · B: ~1 ms. 10,000,000 numbers: A: ~5.8 days · B: ~0.1 s. Version A didn't just get a little slower. It fell off a cliff.

**Slide 5.** Growth beats hardware. Buy a machine 100× faster Linear algorithm: 100× more data. Quadratic algorithm: 10× more data. Exponential algorithm: about 7 more elements.

**Slide 6.** The point. The curve belongs to the algorithm The shape of the growth curve is a property of your algorithm, and no amount of hardware budges it. That is why we count operations, not seconds.
