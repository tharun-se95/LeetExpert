## Alt text (per slide)

**Slide 1.** Spot the bug: Evaluate Reverse Polish Notation. A 12-line Python function, eval_rpn: def eval_rpn(tokens): / stack = [] / for t in tokens: / if t in ("+", "-", "*", "/"): / b, a = stack.pop(), stack.pop() / if t == "+": stack.append(a + b) / elif t == "-": stack.append(a - b) / elif t == "*": stack.append(a * b) / else: stack.append(a // b) / else: / stack.append(int(t)) / return stack[0]. It passes the sample test: eval_rpn(['2', '1', '+', '3', '*']) gives 9. Find the input that breaks it. Comment it, then swipe.

**Slide 2.** Hint. The same code, with line 9 highlighted. The problem says division truncates toward zero. Does // ?

**Slide 3.** The input that breaks it: eval_rpn(['-13', '5', '/']). Returns -3. It should be -2.

**Slide 4.** The fix. One line changes. else: stack.append(a // b) becomes else: stack.append(int(a / b)). JavaScript, same bug: else stack.push(Math.floor(a / b)); becomes else stack.push(Math.trunc(a / b));.

**Slide 5.** Why. // rounds down, toward minus infinity. When the true quotient is negative and not whole, that is one below what truncating gives. From the course: Evaluate Reverse Polish Notation, in Stacks.
