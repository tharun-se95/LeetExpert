## Alt text (per slide)

**Slide 1.** Spot the bug: Partition Equal Subset Sum. A 11-line Python function, can_partition: def can_partition(nums): / total = sum(nums) / if total % 2: / return False / target = total // 2 / dp = [True] + [False] * target / for num in nums: / for cap in range(num, target + 1): / if dp[cap - num]: / dp[cap] = True / return dp[target]. It passes the sample test: can_partition([1, 5, 11, 5]) gives True. Find the input that breaks it. Comment it, then swipe.

**Slide 2.** Hint. The same code, with line 8 highlighted. Each number may be used once. Can this loop use the same number twice?

**Slide 3.** The input that breaks it: can_partition([1, 2, 5]). Returns True. It should be False.

**Slide 4.** The fix. One line changes. for cap in range(num, target + 1): becomes for cap in range(target, num - 1, -1):. JavaScript, same bug: for (let cap = num; cap &lt;= target; cap++) { becomes for (let cap = target; cap &gt;= num; cap--) {.

**Slide 5.** Why. Counting up, dp[cap - num] may already include this num, so it gets counted again. Counting down reads only values from before num was considered. From the course: Partition Equal Subset Sum, in Dynamic Programming.
