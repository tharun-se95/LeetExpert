# leetExpert brand reference

Source: leetexpert.com homepage as of September 2026. If the user gives newer facts,
theirs win; update this file.

## Name and tagline

- Written **leetExpert** (lowercase "leet", capital E). Never "LeetExpert", "Leet Expert"
  or "LEETEXPERT" in copy.
- Eyebrow line: **DSA for the age of AI**
- Headline: **Agents write the code. You decide if it's right.**
- Supporting lines used on the site: "The code is cheap now. Judgment isn't." /
  "See it before you solve it." / "Come back tomorrow."
- Site theme color: #1e293b (slate). Use as the anchor dark color unless the user
  provides brand assets.

## What the product is (safe to state)

- A structured, interactive course in data structures and algorithms.
- 24 modules, 220 lessons, 116 problems, organized in five stages: Foundations; Linear
  Structures; Techniques on Linear Data; Recursive & Hierarchical; Global Reasoning
  (greedy, graphs, DP).
- Problems run in the browser in Python or JavaScript, with nothing to install. Lessons
  teach in Python and TypeScript.
- Features:
  - **Watch**: narrated video and audio walkthroughs.
  - **Tracers**: step through code line by line.
  - **Concept maps**: each module as an expandable map.
  - **Coach**: names the case that broke your draft and points to a hint instead of
    handing over the fix.
  - **Complexity stage**: know the target cost and why it matters.
  - **Practice**: all 116 problems in one workspace.
  - **Cheatsheets**: 21 of them, built around cues, patterns, targets and traps.
  - **Streak heatmap**: every practice day lights a square; consistent practice earns credits.
- Pricing model: early modules are free; later modules unlock one at a time as you reach
  them. Do not state specific prices unless the user supplies them.
- No CS degree needed: if you can write basic loops and functions, you can start.

## Audience

1. Engineers preparing for interviews.
2. Students breaking into software.
3. Working engineers who use AI coding tools and want to judge what those tools write.

Write for someone technical and busy: a developer on their phone between tasks. Assume
they know what a loop is; don't assume they remember what amortized means.

## Voice

- **Direct and calm.** Short sentences. Confident without hype.
- **Specific over general.** "Your window never shrinks, so this is O(n²)" beats "Avoid
  common mistakes!"
- **Respects the reader.** The coach "names the case that broke"; the brand never mocks
  people for not knowing something.
- **Dry, light wit is fine;** memes are fine sparingly if the joke teaches something.
- No emoji walls. At most one or two per caption, and only when they add meaning.
- Avoid: "crush", "grind", "10x", "hack", "secret trick", "guaranteed offer", and
  fear-based AI-replacement framing.

## Claims that need a real source

The homepage's learner section is explicitly marked as placeholder, to be replaced before
launch. Do **not** use any of these in posts:

- "2,400+ engineers learning", "18,000 problems solved", "4.8/5 average lesson rating"
- Any of the named learner quotes (Priya Raman, Marcus Webb, Aiko Tanaka, Diego Alvarez,
  Fatima Noor, Liam O'Connor, Sofia Petrova, Kwame Mensah)

Likewise, don't invent user counts, outcomes ("landed a FAANG offer"), ratings, press
mentions, or partnerships. When a post would benefit from social proof, leave a
`[CONFIRM: real stat/testimonial]` slot and tell the user.
